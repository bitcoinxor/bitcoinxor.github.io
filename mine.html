The difficulty reset. The race is on.

On 29 August 2026 the enforcing chain's proof-of-work changed to BLAKE2b-256, and every SHA256d ASIC on earth became irrelevant on it. The hardware that took its place was waiting in closets: resurrected Sia-era BLAKE2b rigs, hashing from block one. The final parameters, the day-one reality, and where you actually fit.

The final parameters

QuestionAnswer
New hash algorithm BLAKE2b-256 live — selected 2026-08-11 by a deterministic public procedure
Activation By height, 961640 — first BLAKE2b block mined 2026-08-29 22:14 UTC live
Header & hashing construction final — a redesigned 164-byte header: staged commitments hide most fields from the mining hardware, BLAKE2b-256 runs twice, and the result is XORed with a mask derived from a secret xor_key. Official test vectors ship in the node source tree.
Difficulty reset final — the frozen SHA256d difficulty divided by 222: the chain reopened at difficulty ≈30.4 million
Official node release Bitcoin Knots v29.4.1 release-candidate series shipped — see run a node, including the config line it refuses to start without

The honest consequence, updated for reality: at difficulty ≈30.4 million, finding a block takes on the order of 1017 hashes. Within the first day the network was producing blocks every few minutes — hashrate in the hundreds of terahashes per second, essentially all of it resurrected Sia-era ASIC hardware. The much-discussed CPU/GPU window never existed: the chain opened already at ASIC scale. Solo mining with hardware you already own is a lottery ticket, not a plan.

CPU & GPU — xorminer

xorminer is an open-source getblocktemplate miner built for exactly this event. It talks to your own node, builds its own block templates, and treats the hash function as a pluggable kernel:

  • The plumbing — templates, coinbase construction, submission, stale-tip handling — is tested end-to-end against fork-simulation networks, and a byte-exact Python reference of the final hash pipeline passes all of the official test vectors from the node source tree.
  • The kernel update for the final 164-byte header (two BLAKE2b passes over staged messages, plus the xor-key mask) is in progress — the previous kernels implement the pre-release draft construction and cannot mine the live chain yet.
$ git clone https://github.com/bitcoinxor/xorminer
$ python3 -m xorminer --help

Realistic expectations, with the fork behind us: at network scale a CPU or GPU will essentially never find a solo block. Where they still matter is pooled mining — contributing small shares to a pool — and testing, development, and private networks. That is the direction this tooling serves now.

The giants woke up — Sia-era BLAKE2b ASICs

The twist this site flagged before fork day played out exactly: BLAKE2b had been ASIC-mined before. The Sia network's 2018-era hardware — Obelisk SC1, iBeLink BM-S3, and boxes built on the same chips — hashes BLAKE2b at rates no GPU touches, and the final header design courts it deliberately: the construction supports four ASIC message profiles, and profile 0 presents the hardware an 80-byte message in the shape of a Sia mining job. Resurrected Sia fleets are the network's hashrate today.

  • If you own retired Sia hardware: it went from closet paperweight to productive miner in one fork. Power it on, check it POSTs, find your controller passwords.
  • Per-vendor compatibility is being mapped in the open — a community tested-device compatibility matrix already exists. Detailed per-unit guides land here as we can verify them.

Pooled mining without custody — xorpool

Solo mining at network scale is a lottery. xorpool is a pool coordinator designed so that the pool never holds your funds: every found block pays miners directly in its coinbase, split over a published share window, and miners build their own block templates. Zero pool fee. Python and Java implementations, open source, tested on fork-simulation networks.

The final header design has a role written into it for pools: the secret xor_key masks the block hash so that a miner can verify its own shares but cannot tell a share from a winning block — only the key-holder can, which defeats block-withholding attacks against the pool. Adapting xorpool to the final construction is in progress; it is not yet operating as a public pool.

Where to plug in, concretely
  • Run a synced v29.4.1 node on the enforcing chain — it's the one prerequisite everything else needs, and it now takes one extra config line. Guide.
  • Own Sia-era BLAKE2b hardware? Check the community compatibility matrix and get it on the network.
  • Have a wallet address of your own ready for coinbase payouts (wallet safety first).
  • Watch this page and @bitcoinxor — the header-v2 kernels, per-unit ASIC guides, and pool details land here as they're finished and verified.
