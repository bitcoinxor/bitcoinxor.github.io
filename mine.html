Difficulty resets. So does the race.

When the proof-of-work changes, every SHA256d ASIC on earth becomes irrelevant on this chain — and for a window, hardware you already own competes: CPUs, GPUs, and a wave of resurrected BLAKE2b-era mining rigs. What's decided, what isn't, and how to be ready.

Decided vs. pending

QuestionStatus
New hash algorithm BLAKE2b-256 announced — selected 2026-08-11 by a deterministic public procedure
Activation date 1 September 2026 proposed
Exact header & hashing construction pending — a draft design is circulating; no final code published
Difficulty reset & retarget rules pending
Official node release for the fork pending

The honest consequence: nobody can ship a final miner yet, including us. Anyone selling you day-one hashrate, cloud contracts, or "fork-ready firmware" before the specification exists is guessing or scamming. What you can do now is have tested plumbing ready — that's what's below.

CPU & GPU — xorminer

xorminer is an open-source getblocktemplate miner built for exactly this event. It talks to your own node, builds its own block templates, and treats the hash function as a pluggable kernel:

  • The CPU reference kernel works today — including BLAKE2b-256 — and is tested end-to-end against fork-simulation networks.
  • GPU kernels plug in behind a small documented subprocess protocol. The CUDA kernel ships when the final construction is published — the protocol and everything around it is ready now.
$ git clone https://github.com/bitcoinxor/xorminer
$ python3 -m xorminer --help

Realistic expectations: immediately after a difficulty reset, ordinary CPUs can find blocks. As hashrate floods in, difficulty follows. A window measured in days, not months — the preparation is the point.

The sleeping giants — Sia-era BLAKE2b ASICs

Here's the twist most day-one plans miss: BLAKE2b has been ASIC-mined before. The Sia network's 2018-era hardware — Obelisk SC1, iBeLink BM-S3, and boxes built on the same chips — hashes BLAKE2b at rates no GPU touches, and thousands of these units are sitting in closets, functionally worthless. If the final construction leaves them usable, they are the real day-one hashrate.

  • If you own retired Sia hardware: don't sell it yet. Power it on, check it POSTs, find your controller passwords.
  • Whether — and exactly how — each vendor's firmware can drive the new chain depends on final spec details. detailed per-unit guides land here when the spec does.

Pooled mining without custody — xorpool

Solo mining after the reset is a lottery. xorpool is a pool coordinator designed so that the pool never holds your funds: every found block pays miners directly in its coinbase, split over a published share window, and miners build their own block templates. Zero pool fee. Python and Java implementations, open source, tested on fork-simulation networks.

Being ready, concretely
  • Run a synced node on the enforcing chain now — it's the one prerequisite everything else needs. Guide.
  • Clone and run xorminer against your node today; the plumbing you test now is the plumbing you'll mine with.
  • Have a wallet address of your own ready for coinbase payouts (wallet safety first).
  • Watch this page and @bitcoinxor — when the spec lands, the final kernels, ASIC guides, and pool details land here.
